# 品質檢查改善計畫

## 已確認的問題

- Lighthouse 在 push 後只等 30 秒，可能測到部署前的版本。
- App Check 驗證失敗仍被當成已就緒，後續統計 callable 因強制驗證而回覆 401。
- 首屏載入不必要的 reCAPTCHA 腳本與第三方 Cookie。
- 正式站的 Sentry DSN 指向無效專案，回覆 ProjectId；管理介面存在有效 React 專案。
- Lighthouse 缺漏分數只警告不失敗；報告資料夾以隱藏目錄命名，未正確保存 artifact。

## 實作順序與驗收

1. 部署成功後才啟動正式站品質檢查，核對完整 commit 對應 version.json；測量前後版本需一致。
2. 首次點擊、鍵盤、觸控或捲動後才啟動驗證及統計；沒有 token 不送受保護請求，且不把統計回填誤判為成功。
3. 修正現有 Sentry 公開 DSN，驗證原本的錯誤監控連線。
4. 測試驗證失敗、逾時、初始化共用、每次檢查 token、未登入拒絕送出與部署版本不符。
5. 建置、提交、部署，再以正式站隔離瀏覽器及 Lighthouse 驗證。

## 保留的限制

- 不變更 enforceAppCheck、0.5 風險門檻、伺服器限流或資料存取規則。
- 不使用 debug token，不辨識 Lighthouse 特別放行，也不降低品質分數門檻。
- 原本非阻擋的效能分數與 budget.json 預算維持觀察並保存報告；實測數字另行回報。
- 統計同步延後到首次操作；只閱讀而未操作的造訪不會立即同步，未通過驗證者不計入雲端加總。
- 瀏覽器自動化的驗證拒絕不能直接推論為所有一般訪客都失敗。
