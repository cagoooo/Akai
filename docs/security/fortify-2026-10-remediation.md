## 結論與證據邊界

本次要優先加固公開頁面的輸入處理，並另行處理資料寫入權限。237 筆是靜態掃描告警，不能直接解讀為 237 個可利用漏洞，更不能據此判定網站已遭入侵。就像校園安全檢查先標出疑似危險處，仍須確認現場用途與可達性，才能決定修繕或附證據排除。

本紀錄是類別層級的初步複核與改善計畫，不是逐筆弱點結案清單。第一階段已完成發布，第二階段原始碼變更仍須經主線審查、必要測試、建置、既有發布流程與正式資產核對；只有實際完成的驗證才能補列為通過。發布成功不等於 Fortify 告警已逐筆結案。

## 雲端唯讀查核

實際取得的 API 金鑰清單共 2 把，只查設定，不取得或輸出金鑰值：

- Firebase 瀏覽器金鑰已有瀏覽器來源限制，包含本地開發、既有 GitHub Pages 網域及 Firebase Hosting 網域；同時已有 Firebase 相關 API 白名單，未包含 `generativelanguage.googleapis.com`。
- Embedding 後端金鑰僅允許 `generativelanguage.googleapis.com`。沒有瀏覽器來源限制不等於前端金鑰未設防，須依後端 Secret 用途評估；本輪未變更其限制。
- 部分瀏覽器來源使用網域萬用字元，後續可先盤點實際使用的正式入口再評估縮小範圍。不能未確認使用者入口就直接修改，造成正式登入中斷。

## 第二階段：資料寫入權限與評分一致性

以下段落記錄基準提交 `3c1645f6` 的問題與處置方向。第二階段已新增對應原始碼與隔離測試，完整規格、舊資料相容及分階段發布見 [評論與評分資料保護規格](review-data-protection.md)；本輪尚待 CI、部署與正式驗收，未對正式資料做攻擊重現，也未改變登入方式或其他集合規格。

### 評論與點讚

基準規則的 `toolReviews` 新增條件只要求有認證身分，未約束資料中的 `userId` 必須等於當前身分。站台會自動提供匿名身分，因此「有登入」不能等同「已用 Google 確認身分」。就像發了訪客貼紙，不代表訪客可代替別人簽名。

最小修補應沿用目前登入方式，限制欄位白名單與必要欄位，要求作者是本人、工具代碼及評分型別正確、評分為 1–5、評論長度有上限、初始點讚為 0 且名單為空、建立時間為伺服器時間。資料規格須與 `reviewService.ts` 現有 `toolTitle`、可為 `null` 的 `userPhoto` 等欄位相容。

基準的作者修改分支容許改動全部欄位；應限定可編輯的評論、評分與編輯標記，保護作者、工具與建立時間。基準的點讚分支只限制欄位名稱，不能保證票數正確；應驗證只能加入或移除自己的 UID 一次、其他人的 UID 不變、票數對應合法變更且不為負。舊文件若缺欄位，須先確認相容策略，不在正式資料上直接批次補寫。

`reviewReplies` 有前端服務，但本機規則沒有對應開放規則，依預設拒絕。需另外確認功能需求；不能為了讓請求成功便新增寬鬆權限。

### 工具評分統計

基準 `toolRatings` 規則允許任何認證身分直接寫入，而基準前端 `updateToolRating()` 以先讀、再計算、再覆寫方式更新。這像兩個同學同時拿到舊計票表，各自算完交回，後交的可能蓋掉先交的結果；也可能有人直接把總票數改掉。

須先把統計更新移交後端可信交易或等效的原子操作，涵蓋評論新增、評分修改與刪除。事件重試要具備冪等性，避免重複計票；不得只處理新增事件。前端讀取保持現有用途，等後端與前端契約驗證完成後，再禁止前端直接寫入。不能先關權限造成合法評論失效。

若需要重建既有統計，應另列資料遷移範圍、備份、回復方法與授權，不能將原始碼優化當成覆寫正式統計的授權。

### 成就與其他集合

`achievements` 本機規則允許任何認證者寫入；`userAchievements` 允許任何認證者讀寫。已讀取的成就功能使用 LocalStorage，未找到對應 Firestore 呼叫。後續可在確認無外部使用者後移除未使用的寬鬆規則，或按實際資料規格限制管理員與本人。不得猜測文件 ID 結構後直接套用 UID 權限。

既有收藏與最近使用紀錄有本人 UID 條件；其他集合亦須按實際用途分別檢查，不能藉本次工作一次更換整套登入或架構。

### 權限驗證計畫

專案已有 `tests/firestore.rules.test.ts`、`npm run test:rules` 與 Pages 工作流的規則測試門檻，使用隔離的 `akai-rules-test` 模擬器專案。原有測試主要涵蓋分析、公開統計、錯誤日誌與許願池；第二階段另新增評論規則與後端評分聚合模擬器測試，尚待本輪 CI 驗證，成就集合未擴充或調整。

後續必要測試：

1. 分別測試未認證、匿名、一般 Google 身分及管理員；逐項驗證合法操作成功與非法操作拒絕，避免全部拒絕卻誤認為安全。
2. 拒絕偽造作者、變更工具代碼或建立時間、額外欄位、越界／非整數評分、過長或不合規文字。
3. 拒絕一次增加大量點讚、重複點讚、替別人增刪 UID、負數票數；允許本人合法點讚及取消。
4. 前端不能直接新增、覆寫或刪除統計；後端新增／改評分／刪除／重試／並行事件的結果一致，不重複計票。
5. 成就集合依最終用途驗證本人隔離、管理員權限或完全禁止寫入，並確認目前本機成就功能仍正常。
6. 發布前核對本機規則與實際部署內容。正式站僅使用隔離測試資料與已授權操作；涉及會觸發正式通知的提交，須採隔離環境或另行安排，不使用既有個資做測試。
